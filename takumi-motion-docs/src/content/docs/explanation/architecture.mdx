Takumi Motion is a bridge between two worlds: high-level React (or raw HTML) authoring, and a Rust rasterizer that renders CSS-style layouts natively. The bridge is deliberately narrow — a JSON timeline, a static markup tree per frame, and integer milliseconds.

## The pipeline

<Code lang="text" code={`AUTHOR    React components or templates produce a node tree + TimelineJSON
PLAN      Scene windows, transitions, and frame grids resolve up front
CAPTURE   Each frame renders to static markup (pure function of frame index)
COMPILE   The timeline bakes onto a shared fps grid (CSS keyframes)
RASTER    The Rust engine (takumi) renders markup + styles to pixels
ENCODE    GIF / WebP / APNG encoders emit files; post-processing runs`} />

Four properties hold everywhere:

- **Determinism** — `Math.random` is frame-seeded, engine time is integer ms, and no network or clock reads happen during render. Same input, same bytes.
- **Ahead-of-time timelines** — nothing animates "live". The engine samples authored tracks at frame indices and merges byte-identical frames into chunks.
- **Rust rasterization** — the takumi engine (via `@takumi-rs/core`, a prebuilt native module) lays out and paints each frame; no headless browser exists in the pipeline.
- **The report is the API** — every render returns its files, budgets, lint findings, seam verdict, and timings as data.

## Capture lifecycle in detail

<Code lang="text" code={`PROBE    <Banner> registers meta + scene inputs (children do not render yet)
PLAN     planBanner() computes frame-exact scene windows
PREWARM  each scene's opening frame renders once (FitText/Morph discovery;
      outputs are discarded — components may see one extra render per scene)
FRAMES   the real per-frame loop produces the markup that gets encoded
CHUNK    byte-identical adjacent frames merge
LINT     style trees + markup + registry findings assemble report.lint`} />

The prewarm pass is why `<FitText>` and `<Morph>` can measure through the real renderer and still render synchronously in the frame loop. Prewarm outputs never reach the encoder.

| Concern | Where it lives |
| --- | --- |

| Verification | `renderWithAudit`, `checkBanner`, `auditExtents`, lint channel, `explainCapture` |
| Terminal | the `takumi-motion` binary |

## Why not a browser?

A headless browser brings nondeterminism (font hinting, timers, layout races), heavy startup cost, and a byte-output floor. The Rust engine renders the same CSS subset natively and fast — the v1.0 benchmarks record an 80-frame banner end-to-end in ~37 ms, serial. The trade is a bounded style property set (`SUPPORTED_STYLE_PROPS`), which the type system and the `TM_UNKNOWN_STYLE_PROP` lint make explicit.
