Quatre outils d'inspection sont livrés avec le moteur. Ils répondent à des questions différentes — choisir le bon économise des cycles de rendu.

## Les outils en un coup d'œil

| Outil | Ce que vous obtenez | Source de vérité | Idéal pour |
| --- | --- | --- | --- |
| `--filmstrip` | N stills exacts au moteur dans un seul HTML autonome | Les pixels réellement livrés | Relire des diffs — la sortie est octet-déterministe |
| `preview` | Un HTML jouable du CSS capturé | Layout approximatif | Scrubber le timing du mouvement |
| `storyboard` | Une planche contact PNG étiquetée de la timeline | Cellules rasterisées par le moteur | QA visuelle de toute la timeline |
| `renderStill` | Une frame PNG | Exact au moteur | Aperçus de liens, avatars, frames dorées |

## Filmstrip exact au moteur

Chaque cellule est rendue par le moteur Rust — ce que vous relisez est ce que vous livrez :

<Tabs>
  <TabItem label="6 frames régulièrement espacées">
<Code lang="sh" code={` npx takumi-motion render banner.tsx --filmstrip`} />
  </TabItem>
  <TabItem label="Frames explicites">
<Code lang="sh" code={` npx takumi-motion render banner.tsx --filmstrip 0,15,30`} />
  </TabItem>
  <TabItem label="10 frames">
<Code lang="sh" code={` npx takumi-motion render banner.tsx --filmstrip 10`} />
  </TabItem>
</Tabs>

Le filmstrip est un HTML autonome et octet-déterministe, donc il diffe proprement dans les pull requests. Forme programmatique : `renderFilmstrip` (export racine) — accepte les bannières react, les sources HTML et les nœuds+timeline déclaratifs de la même façon.

## Player d'aperçu CSS

<Code lang="sh" code={`npx takumi-motion preview banner.tsx -o banner-preview.html`} />

Le player rejoue le CSS capturé dans un navigateur — bien pour ressentir le mouvement, approximatif pour le layout. Le GIF/WebP encodé reste la source de vérité ; quand ils sont en désaccord, faites confiance à la sortie encodée.

## Planche contact storyboard

Le storyboard rend une grille PNG étiquetée de toute la timeline (cellules rasterisées par le moteur — la planche elle-même est un document takumi) plus un JSON sidecar avec les indices de frames échantillonnés :

<Code lang="sh" code={`npx takumi-motion storyboard reel.tsx --frames 12 --columns 4 --out ./qa`} />

Utilisez-le pour relire l'ordre des scènes, les transitions et le comportement de jointure en un coup d'œil. Forme programmatique : `renderStoryboard` avec `{ banner, frames, columns, scale }`.

## Stills uniques

<Code lang="sh" code={`npx takumi-motion render banner.tsx --still        # frame reposée (~60% de la timeline)
npx takumi-motion render banner.tsx --still 0      # frame explicite`} />

Les bannières bouclantes poster et still valent par défaut la frame 0 — la frame d'atterrissage. `renderStill` renvoie `{ png, bytes, path }` et supporte les trois chemins de source.

<Aside type="tip">
  Associez le filmstrip à `--explain` : le filmstrip montre quelles frames existent, le X-ray montre pourquoi chacune existe. Ensemble ils localisent le gaspillage d'octets en une passe.
</Aside>
