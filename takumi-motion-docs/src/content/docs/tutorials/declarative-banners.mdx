Not every banner needs a component tree. Takumi Motion ships four deterministic banner recipes — `typewriter`, `countup`, `sweep`, and `cascade` — plus a declarative timeline API. In this tutorial you render a template-based banner from a plain TypeScript file, then emit the full multi-preset asset kit.

## Prerequisites

- Node.js 22 or later
- `takumi-motion` installed (see [Your First Banner](/tutorials/first-banner) for installation)

## 1. Render a template

Templates are functions that return a `BannerResult` — an element plus a compiled-ready timeline. Create `release-banner.ts`:

<Code lang="ts" code={`import { gradientSweepBanner, renderBanner } from "takumi-motion";

const result = await gradientSweepBanner({
    title: "v2.4 — no more cold starts",
    subtitle: "cold starts down 96%",
    theme: "dracula",
});

const report = await renderBanner({
    node: result.element,
    timeline: result.timeline,
    preset: "readme",
    outDir: "./out",
    baseName: "release",
});

console.log(report.totalBytes, report.overBudget);`} />

Run it:

<Code lang="sh" code={`node release-banner.ts`} />

You get `./out/release.gif` and `./out/release.webp` plus a poster PNG. The template bakes a strict loop seam, so the animation repeats without a visible cut.

## 2. Understand the shared template props

All four templates share the same option vocabulary (`TemplateStyleProps`):

| Prop | Type | Default | Meaning |
| --- | --- | --- | --- |
| `theme` | `ThemeInput` | `"midnight"` | Color theme name or partial theme object |
| `motion` | `"snappy" \| "smooth" \| "playful" \| "mechanical"` | template default | Personality preset driving easing and stagger |
| `font` | `FontSpec` | theme default | Google Font name or spec |
| `width` / `height` | `number` | 850 / 200 | Logical canvas size in pixels |
| `fps` | `number` | 20 | Frames per second of the baked timeline |
| `renderer` | `TakumiRenderer` | shared renderer | Pre-built renderer instance for reuse |

Each template adds its own props — for example `typewriter` takes `text`, `tagline`, and `speed` (milliseconds per character); `countup` takes a `stats` array of `{ label, value, suffix?, decimals? }`. The full signatures live in [Presets, Themes & Fonts](/reference/presets-and-themes#banner-templates).

## 3. Use the CLI for one-off renders

The `render` command loads a module and renders whatever it exports — a template result, an element-plus-timeline object, or a sync/async function returning either. Create `banner-cli.ts`:

<Code lang="ts" code={`import { cascadeBanner } from "takumi-motion/recipes";

export default await cascadeBanner({
    title: "takumi-motion",
    tagline: "deterministic banners from code",
    accent: "#DF4D24",
});`} />

Then render it from the terminal:

<Tabs>
  <TabItem label="pnpm">
<Code lang="sh" code={` pnpm exec takumi-motion render banner-cli.ts --preset readme-wide --out ./out`} />
  </TabItem>
  <TabItem label="npx">
<Code lang="sh" code={` npx takumi-motion render banner-cli.ts --preset readme-wide --out ./out`} />
  </TabItem>
</Tabs>

The loader resolves, in order: the module's default export, a `banner` export, then an `element` export. It accepts React elements, `defineBanner` functions, and `{ element, timeline }` template results alike.

## 4. Emit the full asset kit

The `--kit` flag renders a banner across several presets plus a static reduced-motion twin — the complete asset set for a project README:

<Code lang="sh" code={`pnpm exec takumi-motion render banner-cli.ts --kit --out ./assets`} />

Programmatically, the same call is `renderKit`:

<Code lang="ts" code={`import { renderKit } from "takumi-motion";

const kit = await renderKit(bannerResult, { outDir: "./assets" });
console.log(kit.files); // [{ path, role }, ...]`} />

The kit writes `<base>-<preset>.<ext>` files for the `readme`, `readme-hd`, and `readme-lean` presets, plus `banner-static.png`. The CLI exits with code 2 when any variant exceeds its preset's byte budget.

<Aside type="caution">
  `--kit` supports declarative banners only. The React path prints a warning and renders normally.
</Aside>

## 5. Author a custom timeline

When templates do not fit, build a timeline directly. `createTimeline` mirrors Motion's API — targets, keyframes, transitions — and renderers consume its JSON form. Timeline JSON is the interchange format every render path accepts:

<Code lang="ts" code={`import { createTimeline, renderBanner, h } from "takumi-motion";

const node = h("div", { style: { fontSize: 42, fontWeight: 700 } }, "ship it");

const timeline = createTimeline({ fps: 20 }).add(
    node,
    { opacity: [0, 1], y: [-24, 0] },
    { at: 0, duration: 600 },
);

const report = await renderBanner({
    node,
    timeline: timeline.toJSON(),
    outDir: "./out",
});`} />

`renderBanner` runs `compileTimeline` internally — bake it yourself only when you need the CSS output for inspection. Timeline transforms (`shiftTimeline`, `concatTimelines`) compose longer sequences declaratively — the data equivalent of stacking scenes.
